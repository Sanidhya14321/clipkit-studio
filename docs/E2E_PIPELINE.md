# ClipKit Studio: End-to-End Pipeline and Fix Prompt

A self-contained prompt for an agent starting with no prior context. It explains what ClipKit is for, how the whole pipeline must work from user input to export, what state the project is believed to be in, and how to fix the gaps in priority order, as efficiently as possible.

## 1. The aim

ClipKit is a plugin for coding agents (Claude Code, Codex and others) that edits and generates video through a live studio on localhost. The single goal that outranks everything else:

The finished video must be clearly better than what a general AI agent produces from the same prompt: modern, fast-paced, music- or speech-driven, cut on the rhythm, with clean captions and well-used assets, no collisions, and every moment editable by the user.

"Clearly better" is measured, not claimed: energy gates (still ratio, longest hold, cuts per 10 seconds), beat or speech alignment, zero collisions, loudness and playback checks, the output-only evaluator score, re-prompts needed to fix one moment, tokens used, and a blind human A/B rating against a vanilla agent.

The second goal: the user can step in and edit anywhere, at any time the agent is not working on that part, and the agent continues from the user's changes.

## 2. How the whole pipeline must work

### 2.1 Common start

1. The user types a request in their agent (for example: edit this clip into a reel, or make a 30 second launch video). The studio starts automatically on localhost and opens in the browser.
2. ck detects the mode from evidence: a video file means EDIT (or HYBRID if the request also asks for generated scenes); no video means GENERATE.
3. The Brief page opens with smart defaults. Fast-paced is the default for every video; slower only if the user asks. The user confirms, adjusts or skips.

### 2.2 EDIT path (the user gives an MP4)

1. Ingest: probe the file, make a proxy, extract audio. The original is never modified.
2. Speech to text: transcribe the speech with word-level timestamps (local whisper by default, cloud speech-to-text as an option). Note: this is speech-to-text, not text-to-speech. Text-to-speech is only for generated voiceover.
3. Understand the content: from the transcript, build a compact content map: topics, key lines, emphasis words, hooks, filler words, retakes and pauses. The agent reads this map, not the raw transcript.
4. Rhythm source: the speech itself sets the base rhythm (phrases and emphasis words). If music is added (from the user or the licensed library), its beat grid is measured and cuts align to both speech boundaries and beats.
5. Edit Decision Plan (section 3): cuts, punch-ins, b-roll inserts, captions, text and graphics, sound hits and transitions, each placed on a speech boundary or beat and converted to exact frames by code.
6. Captions come straight from the word timestamps of the kept speech, so they are exact and cheap.
7. Build, verify, hand off to the user (section 2.4).

### 2.3 GENERATE path (no footage)

1. The Brief asks only what matters and is not already known: goal and call to action, audience, length, aspect, rhythm source, pace (default fast), look or mood, voice (AI, recorded, cloned or none), music.
2. Rhythm source, in this order of preference: the user's music track (measure its beat grid), a library track chosen by tempo band and energy, a voiceover (voice-first timing), or a content-derived grid (a tempo chosen from the pace, with beats generated by code).
3. Script and beat sheet: the agent writes the message as one or two words or one idea per beat, grouped into blocks, with the hook in the first 1.5 seconds and a clear turning point (the drop).
4. Edit Decision Plan (section 3): each block gets a recipe, kinetic block, asset or footage moment, chosen from the curated library, with timing in beats.
5. Build, verify, hand off (section 2.4).

### 2.4 Build, user control and export (both paths)

1. The agent writes changes as small patches into a draft. The user watches the timeline fill in live, pass by pass: structure, audio, text, graphics, transitions, look, polish.
2. Gates run after every pass: energy, rhythm alignment, collisions, safe areas, caption reading speed, loudness. Failures are fixed before moving on.
3. Handoff: the user reviews the draft (accept all, or per change), then edits anything directly: timeline, inspector, keyframes, captions, brief fields, comments, voice commands.
4. Further requests (comments, brief changes, voice) become small scoped jobs; only affected parts change.
5. Export: fast ffmpeg path when possible, full engine render otherwise, then the playback check and the license report.

## 3. The Edit Decision Plan: frame-accurate without frame-by-frame tokens

The user wants decisions made frame by frame. Doing that with the model would be slow and very expensive (a 30 second video at 30 fps is 900 frames). Instead, split the work:

- The agent decides at the level of segments and beats: what happens, in which order, with which asset, and why. That is tens of decisions, not hundreds.
- Deterministic Rust code turns those decisions into exact frames: snapping to speech boundaries and beats, durations, transitions, caption timing, sound onsets, layout and collision resolution.

### 3.1 Shape of the plan (stored in the project as plan.edl)

- Rhythm grid: source (speech, music, voice, generated), tempo if any, beat and downbeat times, speech phrase boundaries, emphasis words, drop.
- Segments in order, each with: id, time range in beats or speech anchors (never raw guesses), role (hook, point, proof, turn, call to action), content (words on screen or kept speech), visual (recipe or kinetic block id, footage range or b-roll query), motion (enter and exit move, punch-in), transition into the next segment, sound (hit type), and caption mode.
- Constraints from the brief: pace, energy targets, one hero element per beat, maximum words on screen.

### 3.2 Who does what

| Step | Done by | Output |
| --- | --- | --- |
| Measure speech, beats, emphasis, scenes | Rust and ffmpeg (plus the local speech and beat models) | Rhythm grid |
| Content map from transcript | Code first (fillers, pauses, retakes); agent marks key lines and hook | Content map, about a few hundred tokens |
| Segment plan | Agent | plan.edl segments as compact JSON |
| Pick assets per segment | ck search over the curated library, agent picks from the top 3 | Asset ids per segment |
| Expand to layers and frames | Recipe expander, layout solver, sound planner (code) | Patches with exact frames |
| Check | Gates (code), one critic image (agent) | Pass, fail and fixes |

A change to one segment re-expands only that segment, so edits stay cheap and local.

## 4. Engines, tools and component libraries: who does what

Use every tool for what it is best at, behind one engine adapter, so the project file never depends on a single engine.

| Tool | Role in ClipKit |
| --- | --- |
| Rust core (ck) | State, patches, locks, stages, gates, the plan expander, layout and collision solver, media analysis orchestration, server, CLI and MCP |
| FFmpeg and ffprobe | Probing, proxies, audio extraction, cuts, speed changes, LUTs, captions burn-in, loudness, scene detection, the fast export path for footage-heavy videos |
| Local speech and analysis models | Word-level speech-to-text, voice activity (pauses), beat and onset detection, face boxes, run from Rust where possible |
| Remotion | Rendering React-based clips and templates (Remotion-native component libraries), and the preview player if it is the chosen engine |
| HyperFrames | Rendering HTML-native compositions with seekable adapters for GSAP, CSS, Lottie, Three.js and Motion, if approved in the engine decision |
| React component libraries (React Bits, Magic UI and similar) | Kinetic text, backgrounds and effects, used through the frame-clock adapters after they pass the determinism test, or re-implemented natively from their cards |
| Web components and plain HTML or CSS | Lightweight overlays, captions and UI mockups that both engines can render |
| Media libraries (licensed SFX, music, b-roll, LUTs, fonts, icons) | Sound kit, music beds, inserts, grades and type, all via vetted cards |

Rules: check DECISIONS.md for the engine decision from Update 5 and follow it; if it is still pending, keep both adapters working on the core clips and do not block the pipeline on it. Every component must be deterministic (same frame, same pixels) before it can be used in a project. License mode decides which assets are allowed.

## 5. Asset selection per segment

- Search the curated fast-paced starter collection first, then the wider catalog. Filters come from the segment: role, aspect, pace, mood, tempo band, license mode.
- The agent sees at most the top 3 candidates per segment as one-line cards and picks one. It reads a full card only when two candidates are close.
- Every placed asset is adapted: text, design tokens, timing to beats or speech, scale and position from the layout solver. A lint rejects unadapted defaults.
- Variety rules: no asset more than twice unless it is a motif; one sound kit and at most two transition types per video.
- Collisions are prevented by the occupancy map and placement order (hero first, then supporting text, then the caption band, then decoration). Overlaps are never left silently.

## 8. Token efficiency (for you and for the shipped agent)

- Code does the measuring and the frame math; the model decides at segment level only.
- The agent reads compact artifacts (content map, grid summary, plan.edl, top 3 asset lines), never raw transcripts, full catalogs or full project JSON.
- Patches, not rewrites; re-expand only changed segments.
- Every agent-facing output has a size cap with a test.
- One critic image per pass at most.
- For your own build work: one step per session when context grows, a 5-line handoff in PROGRESS.md before stopping, subagents for test runs and log reading, rg and ranged reads only.

## 9. Definition of done

- An MP4 with speech becomes a fast-paced edit with exact captions, cuts on speech boundaries (and beats when music is added), punch-ins, sound hits and no collisions, editable in the studio, in one request.
- A prompt with no footage becomes a fast-paced generated video timed to music, voice or a generated grid, with assets chosen per segment and no collisions.
- The user can review the draft, edit anything, and ask for scoped changes that only touch the affected segments.
- All gates enforced; export refuses broken videos; skill and tool agree; benchmark report shows the result against a vanilla agent with medians and run counts.
