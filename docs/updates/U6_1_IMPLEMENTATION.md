## Working implementation

- Audio ingestion uses the same CLI/MCP `sources ingest` operation and a shared trusted Rust analysis callback. It writes cards, read-only audio, provenance, origin/license notices and bounded analysis metadata. Code and docs retain their 2 MiB file cap; audio has a separate 32 MiB cap, with the original 64 MiB source-total cap retained. New cards are grade B technical candidates, not artistic ratings.
- `ck music analyze PATH`, MCP `music_analyze` and `/api/music/analyze` share the same operation. Decoding is limited to a regular local file under 128 MiB and 600 seconds, with a 60-second subprocess timeout and a finite 64 MiB output cap. First-stream channel magnitudes are combined without stereo cancellation. Full data is cached by content hash; compact replies cap timing/energy lists and report omitted counts.
- The detector uses positive RMS-energy flux at 10 ms hops, interval votes and fractional period/phase fitting. Confidence checks timing residuals, duration coverage and occupied energy bins. Silence, phase changes and long silent gaps cannot automatically establish a grid. Returned timing is always unconfirmed and never changes project timing. This is a conservative candidate detector, not a complete musical meter/downbeat tracker. A rich music track can legitimately return no confident tempo. Publisher tempo claims are not treated as measurements.
- Metadata includes decoded envelope peak/RMS, onset candidates, per-second energy, coarse energy-rise candidates and, for ingest, original-source LUFS/true peak where the meter can measure them. Sub-400 ms effects have no integrated LUFS result. Energy rises are not confirmed musical drops. Music cards expose measured tempo-band tags or `tempo-unconfirmed` for search.
- Source monitor plays imported audio and offers Analyze rhythm with explicit confirmation guidance. New audio original-route MIME types support playback. This is source auditioning; the live composition still does not mix the entire audio timeline.
- The explicit native adapter `glitch-text-v1` connects `rendercomp-free/glitch-text` derivation to a typed, deterministic native technique implementation. Derivation records `id`, source asset/hash and adapter version in `project.derived`; layers can render through that `derivedId`. Both server and studio allowlists validate the mapping. This is a native reimplementation based on the card, not execution of the copied source. Other derived files remain unregistered/unexecutable.
- Derived names are immutable. Re-deriving into an existing name is rejected before writes, so neither a conflicting source nor an updated source can overwrite files or leave a stale registered hash. Use a new name for a new revision. New files are cleaned up if registration commit is refused.
- Backend export refuses an unsupported renderer even when `forceReason` requests a quality-gate override. UI guards also disable that export. The native-adapter proof derives, places, previews, renders active glitch frames twice/out of order and exports with actual CC0 audio and a license report.
